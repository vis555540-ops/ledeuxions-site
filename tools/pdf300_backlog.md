# PDF300 백로그 (나중에 할 것)

> 지금 우선순위: ①레몬즙 KYC → 결제 오픈 ②검색 가능한 PDF ③홍보(Product Hunt).
> 아래는 좋은 아이디어지만 **순서상 나중**. 없애는 게 아니라 미루는 것.

## 1. 선택 영역 글자 지우고 다시 쓰기 (형 아이디어 2026-07-29)
- 사용자가 박스를 드래그 → 그 안 글자를 지우고 새 글자를 씀. "급한 사람은 돈 낸다"가 형 관찰.
- **1단계(AI 불필요)**: 스캔 문서·흰 배경·표는 배경색 샘플링 후 덮고 텍스트 얹기. 브라우저에서 가능, 서버 부담 0.
- **2단계(AI 인페인팅)**: 사진·무늬·도장 위 글자. 여기서만 AI가 필요.
  ⚠️ **하드웨어 제약(2026-07-29 실측)**: 미니PC = AMD 내장그래픽, 전용 GPU 없음(코어16/램15GB) → 장당 수 분, 실사용 불가.
  맥미니(애플실리콘 MPS)는 가능하나 부장 본체 겸 백엔드라 상시 부하는 부적절.
  → 상시 서비스할 하드웨어가 지금 없다. 이게 미루는 진짜 이유.
- 과금: pay-per-use보다 **크레딧 팩**(이음 제안)이 나음. 소액결제는 수수료 비중이 큼.
  단 크레딧은 잔액 귀속 대상이 필요 → 계정. 무료 사용자는 계속 무계정 유지하고, 결제자만 키 발급(기존 ld_ 체계 재사용).
- 제품 분리: pdf300에 섞지 말고 별도 하위도메인(이음 제안 imgworks 류)이 맞음. 섞으면 "PDF 도구" 정체성이 흐려짐.

## 2. 진짜 인플레이스 PDF 텍스트 편집 — **하지 않기로**
- 어도비 영역. 한글 폰트 매칭·리플로우가 특히 취약해 결과가 지저분함.
- iLovePDF·스몰PDF도 안 함(걔들 Edit PDF = 위에 텍스트 얹기).
- 우리가 하면 기대치만 올리고 실망을 줌.

## 3. SNS 홍보 스샷 → 메일 → 보상 — **하지 않기로** (2026-07-29 결론)
- 스샷 위조 쉬움 / 검증에 사람 손 필요 / 보상 귀속에 계정 필요 / 레딧·X 스팸 밴 위험.
- 대체: 하단 공유줄(무검증·명예제) → 미터링 켜지면 +10회 자동. 이미 구현됨.

## ⚠️ 1번에 대한 결정적 반대 근거 — 위조 도구가 된다 (형 지적 2026-07-29)
형: "사기 치는 건 안 되지, 범죄에 이용되는 건 안 되지."
**부장과 이음이 둘 다 놓친 각도였고, 이게 하드웨어·품질·시장 근거보다 강하다.**

- 스캔 문서에서 **글자를 지우고 새 글자를 쓰는 기능** = 계약서 금액·영수증 날짜·신분증 번호 위조 도구.
  우리는 누가 무엇을 고치는지 알 방법이 없고, 막을 방법도 없다.
- 선의의 용도(내 서류 오타 수정)와 위조가 **기술적으로 구별 불가능**하다.

### 그래서 선을 이렇게 긋는다
- ❌ **지우고 다시 쓰기(인페인팅)** — 원본 흔적이 사라짐 = 위조. **만들지 않는다.**
- ⭕ **위에 얹기(주석·텍스트 박스)** — 원본이 그대로 남고 덧쓴 게 보임. 양식 작성·메모 용도. 이건 괜찮다.
- ⭕ **가림(redact)** — 이미 있음. 지우는 게 아니라 덮어서 감추는 것이고, 감췄다는 사실이 드러난다.

나중에 하드웨어가 좋아져도 ❌ 항목은 그대로 ❌. 기술 문제가 아니라 성격 문제다.
