Guide: compressing to an exact size

Why a target size

Upload forms rarely ask for "a smaller file". They ask for a number: 300 KB for many public-sector and visa portals, 1 MB or 2 MB for job applications, 5 MB or 10 MB for tender submissions, 20–25 MB for most email services. Guessing a compression level, checking the size, and trying again wastes time. This tool takes the number and does the searching for you.

How it works

Each page is redrawn as a JPG image at a chosen resolution, and the pages are assembled into a new PDF with the same page size as the original. In browser mode (the default) this happens on your own device: the tool starts at JPG quality 72, estimates the resolution that should fit, and refines it (between 30 and 200 dpi) until it finds the highest one under your target. If even 30 dpi is too large, it lowers the JPG quality (50, 35, 22) and searches again. Server mode does the same on our server, starting at quality 75 and stepping down through 65, 55, 45 and 35.

If the file still cannot reach the target at the lowest settings, you get the smallest version it could make, and the result message says it is slightly over. That usually means the document has too many pages for the limit — see the tips below.

Quality versus size

A rough rule for A4 pages: at 300 KB you have about 60–100 KB per page for a three-page document, which is readable at around 100 dpi. At ten pages the budget drops to 30 KB per page and small print starts to smear. If the limit is tight, reduce the page count first: remove blank pages and cover sheets with Rotate & reorder, or submit only the pages the form actually asks for with Split.

The output is always image-based, so text in it cannot be selected. That is normally fine for scans of IDs, certificates and signed forms. For a text-heavy document where you only need a modest reduction, high-quality compression keeps the text layer.

Privacy

In browser mode the file never leaves your device and there is no limit. In server mode the file is processed in memory and returned in the same request; it is not written to a folder or kept. Server use is limited to 10 files per day, counted by an anonymous key stored in your browser.

Common problems

"Slightly over" message. The document has too many pages, or very large pages, for the limit. Cut pages, or split the upload if the portal allows several files.

The portal still rejects it. Check that it is really a size problem. Some portals also reject files with passwords, unusual characters in the file name, or PDF versions they do not expect. A plain name like passport_scan.pdf avoids the second problem.

Daily limit reached. That only applies to server mode. Switch to browser mode, which has no limit.

More questions

Is the result exactly the size I typed?

It is the sharpest version at or under your target. It is usually a little under, because resolution is searched in steps.

What is the largest file I can send?

100 MB per file.

Why is the text no longer selectable?

Every page is redrawn as an image to control the size precisely. That is the trade-off for hitting a number.

Should I type MB or KB?

Whichever the form uses. In browser mode 1 KB is 1,000 bytes and 1 MB is 1,000,000 bytes, so the result is under the limit whichever way the site counts.

Is anything saved on your server?

In browser mode nothing is sent at all. In server mode the file is processed in memory and discarded after the response is sent.
